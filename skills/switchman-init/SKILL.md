---
name: switchman-init
description: Build switchman's routing table from the skills installed on this machine. Run once, then again after adding or removing skills.
disable-model-invocation: true
allowed-tools: Read Glob Grep
---

Rewrite the routing table in `${CLAUDE_SKILL_DIR}/../switchman/SKILL.md` so it matches the skills actually installed.

1. Collect the installed skills:
   - Every skill whose name and description you already see in your context.
   - Manual-only skills (`disable-model-invocation: true`), which are not in your context. Look for them in `~/.claude/skills/*/SKILL.md`, `.claude/skills/*/SKILL.md`, and in each plugin listed in `~/.claude/plugins/installed_plugins.json` (under its `installPath`: `skills/*/SKILL.md`, plus the paths in the `skills` field of its `.claude-plugin/plugin.json`). Find them with the Grep tool (pattern `disable-model-invocation: true`, glob `SKILL.md`), not the shell, and read only their frontmatter. A plugin skill is named `plugin:skill`.
   - Leave out switchman and switchman-init.
2. Group them by kind of task. Start from the current rows (UI/design, bugs, new feature, code review, security, writing) and add a row only when the skills call for it (e.g. database, video, docs). 10 rows max, 3 skills max per row, best first. Leave out skills that don't serve a kind of task (setup, help, settings, stats).
3. Write each name exactly as it is invoked. Add ` (manual)` after manual-only skills.
4. Show the proposed table and ask the user to confirm or adjust it. Write nothing before a yes.
5. On yes, replace only the table under the heading that starts with `## Routing table`, and change that heading to `## Routing table (generated by switchman-init)`. Change nothing else in the file.
6. Confirm in one line, and remind the user to run `/switchman-init` again after installing or removing skills.
